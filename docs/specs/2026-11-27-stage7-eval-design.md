# 7단계 설계: 품질 평가셋 · 반복 측정 · CI

작성일 2026-11-27

## 1. 목표

지금까지 실제 모델 테스트는 "샘플 하나가 통과하는지"만 봤다. 기획안의 품질 지표(전사 오류, 근거 없는 요약, 알림 오탐·누락)를 **숫자로** 보고, 프롬프트나 모델을 바꿀 때 나빠졌는지 알 수 있게 한다.

포함
- 가상 시나리오 평가셋 (`app/evaluation/dataset.py`): 분류 시나리오(정답 항목·부위·식사량·기분·위험 표시·후속 확인 답), 일부러 헷갈리게 만든 사례, 알림 시나리오(방문 순서와 기대 알림)
- 지표 계산 (`app/evaluation/metrics.py`)과 실행기 (`python -m app.evaluation --provider local --repeat 3`)
- CI: 알림 규칙 평가(결정적)를 테스트로 돌리고, 지표 계산은 단위 테스트
- 실제 모델(로컬 qwen2.5:7b, Gemini 무료 등급) 측정 결과를 `docs/eval/`에 남기고 README에 요약

제외
- 실제 녹음 데이터 (가상 데이터만)
- CI에서 실제 모델 호출 (비용·무료 등급 한도·비결정성)
- 자동 프롬프트 튜닝

## 2. 결정과 이유

| 결정 | 이유 |
|---|---|
| 정답 항목은 **분류 + 꼭 들어갈 핵심어**로 맞춘다 | 모델마다 문장 표현이 달라 완전 일치는 의미가 없다. "무릎"이 들어간 말씀 항목이면 맞힌 것으로 본다. |
| 정답에 없는 항목은 **틀린 항목**(정밀도 감점), 다만 `optional`로 허용할 수 있다 | 전사문에 있는 잡담을 항목으로 만들어도 틀렸다고 하기 어려운 경우가 있다. |
| 전사(STT)는 텍스트 시나리오에서 빼고, `--stt`로 `say` 음성의 글자 오류율(CER)만 따로 | STT와 분류 오류가 섞이면 원인을 알 수 없다. |
| 마스킹은 평가에서도 적용 | 실제 파이프라인과 같은 입력으로 잰다. |
| 반복 측정 결과는 **평균과 최소·최대** | 같은 입력에도 결과가 달라서 한 번 결과로는 판단할 수 없다(2·5단계에서 경험). |
| 알림 평가는 CI에서 **전부 맞아야 통과** | 규칙은 결정적이다. 틀리면 회귀다. |

## 3. 지표

| 지표 | 정의 |
|---|---|
| 항목 재현율 | 정답 항목 중 맞힌 비율 |
| 항목 정밀도 | 모델 항목 중 정답(또는 허용)과 맞는 비율 |
| 근거 일치율 | 모델 항목 중 근거 구절이 전사문에 실제로 있는 비율 |
| 부위 정확도 | 부위가 있는 정답 항목을 맞혔을 때 부위가 같은 비율 |
| 부위 오탐 | 부위가 없어야 하는 항목(예: 무릎 담요)에 부위를 붙인 수 |
| 식사량·기분 정확도 | 정답이 있는 시나리오에서 값이 같은 비율, 언급이 없는데 값을 만든 수 |
| 위험 표시 재현율 | 위험 표시가 있어야 하는 정답 항목 중 표시한 비율 |
| 후속 확인 재현율·오답 | 답이 있는 이전 확인 사항을 찾은 비율, 답이 없는데 답을 만든 수 |
| 요약 근거율 | 요약 문장 중 실제 항목 번호를 근거로 단 비율 |
| 알림 정밀도·재현율 | 시나리오별 기대 알림(kind, key)과 실제 미처리 알림 비교 |
| 처리 시간 | 시나리오당 분류 시간 |
