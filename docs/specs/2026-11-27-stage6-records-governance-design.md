# 6단계 설계: 정정 · 이력 · 내보내기 · 보관 · 마스킹 · 사진

작성일 2026-11-27

## 1. 목표와 범위

기획안의 다음 항목을 만든다.

> 동의 철회·담당자 변경 시 접근 권한 갱신. **열람·정정·내보내기 이력 관리.**
> 음성은 **암호화해 임시 저장**하고 검토·확정 후 또는 **보관기한이 지나면 삭제**. 전사문과 확정 기록은 용도에 따라 각각 보관기간과 삭제 기준 설정.
> 전사문의 **이름·연락처 등 불필요한 식별정보 제거**.
> 변화 알림: … **정정 시 재평가**.

양이 많아 PR 두 개로 나눈다.

**PR ① 정정 · 이력 · 내보내기**
- 확정 기록 정정: 항목(분류·내용·불편 부위·위험 표시)과 오늘 상태(식사량·기분)를 사유와 함께 고친다. 이전 값은 정정 이력으로 남는다.
- 정정 뒤 처리: 변화 알림 재평가, 센터 확인 서명 초기화, 승인된 보호자 요약은 다시 확인하도록 승인 취소.
- 감사 로그: 열람(기록, 방문 전 확인, 검색, 보호자 화면), 정정, 내보내기. 기관 담당자가 수급자별로 본다.
- 내보내기: 기관 담당자가 수급자의 확정 기록을 CSV로 받는다.

**PR ② 보관 · 마스킹 · 사진**
- 음성 파일 암호화 저장(Fernet), 처리할 때만 메모리에서 복호화.
- 보관 기간: 확정되지 않은 기록의 음성은 N일 뒤 삭제, 확정 기록의 전사문·초안은 M일 뒤 삭제(확정 항목은 남김). 워커가 주기적으로 실행.
- 전사문 마스킹: 전화번호, 이메일, 주민등록번호 형태를 전사 직후 가린다(AI 분류에 넘기기 전).
- 사진 첨부: 확정 전 검토 화면에서 최대 3장. 다시 인코딩해 EXIF(위치 등)를 지우고 암호화 저장. 직원만 본다.
  - 사진 업로드에도 건강정보 동의 확인(새로 모으는 건강정보). 디코딩 전에 화소 수(4000만)를 확인하고 JPEG·PNG·WEBP 파서만 연다(자동 보안 리뷰 지적 반영).

제외
- 이름 마스킹 (형태소 분석·사전이 필요해 정규식으로는 오탐이 많다. 수급자 이름은 앱이 AI에 보내지 않는 것으로 대신한다)
- 항목 삭제·추가 정정 (후속 확인·요약 근거가 항목을 가리켜서 내용 정정만 둔다)
- 감사 로그 보관 기간·내보내기

## 2. 결정과 이유 (PR ①)

| 결정 | 이유 |
|---|---|
| 정정은 **덮어쓰기 + 이력 행** | 화면·규칙·요약은 현재 값만 보면 되고, 이전 값은 이력에서 본다. 버전 테이블로 모든 조회를 바꾸는 것보다 단순하다. |
| 정정 사유 **필수** | 공식 기록을 고치는 일이라 왜 고쳤는지 남겨야 한다. |
| 정정할 수 있는 사람: **작성자(지금 배정 중)와 기관 담당자** | 다른 요양보호사의 기록은 작성자나 센터가 고친다. |
| 정정 뒤 **서명 초기화**, **승인된 보호자 요약은 승인 취소** | 센터가 확인한 내용이 바뀌었으므로 다시 확인 대기로. 보호자에게 정정 전 내용이 계속 보이지 않게 한다. |
| 알림 재평가 = **이 기록의 근거 제거 → 규칙 다시 평가 → 근거 기록이 둘 미만이면 닫기** | 4단계 규칙 함수를 그대로 쓴다. 닫을 때 처리 결과는 `corrected`(정정으로 조건이 사라짐). |
| 감사 로그는 **누가·언제·무엇을(행동, 수급자, 기록)**만 | 검색어나 기록 내용은 남기지 않는다. 로그 자체가 건강정보를 모으는 곳이 되지 않게 한다. |
| 내보내기는 **기관 담당자만, CSV(UTF-8 BOM)** | 엑셀에서 한글이 깨지지 않는다. 파일 이름에는 수급자 이름 대신 UUID. |
| CSV 칸이 `=`, `+`, `-`, `@` 등으로 시작하면 앞에 `'` | 항목 내용·근거는 AI와 전사문에서 오므로 엑셀이 수식으로 실행할 수 있다(CSV 수식 주입). 자동 보안 리뷰 지적 반영. |
| 정정에도 **건강정보 동의 필요** | 정정은 알림 재평가까지 이어지는 새 처리라 확정과 같은 규칙을 둔다(3단계 "철회 뒤 새 처리 중단"). 자동 보안 리뷰 지적 반영. |

## 4. API (PR ①)

| API | 누가 | 설명 |
|---|---|---|
| `PATCH /records/{id}/items/{item_id}` | 작성자(배정 중)·기관 담당자 | `{category, content, body_part, risk_tag, reason}`. 확정 기록만. 바뀐 게 없으면 422 |
| `PATCH /records/{id}/state` | 같음 | `{meal_level, mood, reason}` |
| `GET /records/{id}` | | 응답에 `revisions` (정정 이력, 작성자 이름) |

## 5. 화면 (PR ①)

- 확정 화면: 항목마다 "정정"(권한 있을 때) → 분류·내용·부위 수정 + 사유 → 저장. 정정된 항목에 "정정됨" 배지, 아래에 정정 이력(언제, 누가, 이전 내용, 사유). 오늘 상태도 정정.
- 수급자 관리(기관 담당자): "기록 내보내기 (CSV)", "열람·정정 이력" 목록.

## 6. 테스트 (PR ①)

- 정정: 사유 필수, 확정 전 기록 409, 다른 요양보호사 403, 기관 담당자 가능, 이력 저장, 서명 초기화, 승인된 요약 승인 취소.
- 재평가: 무릎 → 허리로 정정하면 무릎 알림이 `corrected`로 닫힘, 허리로 같은 부위가 생기면 새 알림, 식사량 정정으로 감소가 사라지면 닫힘.
- 감사 로그: 각 행동이 남고, 검색어·내용이 없음, 기관 담당자만 조회.
- 내보내기: BOM·머리글·행, 이름 없는 파일 이름, 감사 로그.
- 접근 표 추가, E2E: 정정 → 이력 → 알림 닫힘.
